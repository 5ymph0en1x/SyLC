x265.exe — provenance (SyLC MV-HEVC export, Task EX-1)
=======================================================

WHAT
  Standalone x265 HEVC encoder CLI, 8-bit, built WITH MV-HEVC multiview
  support (-DENABLE_MULTIVIEW=ON). No reputable pre-built Windows binary
  ships multiview: the x265 CMake option ENABLE_MULTIVIEW defaults to OFF
  (source: source/CMakeLists.txt line 701; confirmed by Mike Swanson's
  reference guide and MulticoreWare's "MV-HEVC Extension Support in x265").
  Therefore built from the OFFICIAL 4.1 source tarball on this machine.

BUILD-COMPATIBILITY PATCH (source/CMakeLists.txt — NO functional/encoder change)
  CMake 4.x removed support for cmake_policy(SET ... OLD). The x265 4.1
  CMakeLists set CMP0025 and CMP0054 to OLD and required cmake >= 2.8.8,
  which CMake 4.2.1 refuses. Patched exactly (same fix used by Yocto/OE
  "x265: fix build with cmake 4"):
    - CMP0025 OLD -> NEW
    - CMP0054 OLD -> NEW
    - cmake_minimum_required 2.8.8 -> 3.5
  Also passed -DCMAKE_POLICY_VERSION_MINIMUM=3.5. These affect only the CMake
  configure step, not the compiled encoder.

CONFIGURE COMMAND (verbatim)
  cmake -S x265_4.1/source -B build -G Ninja -Wno-dev \
    -DCMAKE_C_COMPILER=/c/msys64/mingw64/bin/gcc.exe \
    -DCMAKE_CXX_COMPILER=/c/msys64/mingw64/bin/g++.exe \
    -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_POLICY_VERSION_MINIMUM=3.5 \
    -DENABLE_MULTIVIEW=ON \
    -DENABLE_CLI=ON \
    -DENABLE_SHARED=OFF \
    -DCMAKE_EXE_LINKER_FLAGS="-static -static-libgcc -static-libstdc++"
  (nasm + ninja on PATH so find_package(Nasm) succeeds -> assembly enabled)
  Build: `ninja -C build`  (89 targets, ~60 s)
