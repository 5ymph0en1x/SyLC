MP4Box (GPAC) — provenance (SyLC MV-HEVC export mux, Task EX-1)
================================================================

WHAT
  GPAC MP4Box CLI — the muxer chosen (EX-1 tranche) to wrap the x265 MV-HEVC
  elementary stream into a QuickTime .mov. MP4Box is the ONLY tested tool that
  emits the Apple/reference-canonical layered structure hvc1 + hvcC + lhvC with
  colr nclx AND a stream our own LavfHevcSource reads back (dogfood PASS).
  ffmpeg (bundled) CANNOT write the lhvC box: `-tag:v hvc1` drops the dependent
  layer's parameter sets -> "PPS id out of range" on read-back; `-tag:v hev1`
  works but is non-canonical (in-band PS, hev1 tag, no lhvC).

WHY MP4Box AND NOT ffmpeg (EX-1 mux tranche — empirical)
  Muxing out_synth.hevc (48-frame synthetic MV-HEVC SBS from x265):
    ffmpeg -f mp4 -tag:v hvc1 : hvc1, colr nclx, view_ids=0,1, but NO lhvC ->
                                LavfHevcSource read-back FAILS (PPS id out of range).
    ffmpeg -f mp4 -tag:v hev1 : hev1, colr nclx, view_ids=0,1, in-band PS ->
                                dogfood PASS, but non-canonical (no lhvC/hvc1).
    MP4Box                    : hvc1 + hvcC + lhvC + colr nclx, view_ids=0,1,
                                "HEVC L-HEVC Import results" -> dogfood PASS.
  Only MP4Box reproduces the reference file's structure
  (docs\hevc_4k24P_main_multiview_1.mp4 = hvc1+hvcC+lhvC).

EXACT COMMAND (shipped)
  mp4box.exe -add "<in>.hevc:fps=<FPS>:colr=nclx,<prim>,<transfer>,<matrix>,<off|on>" -new "<out>.mov"
  e.g. (bt709 limited, 24 fps):
  mp4box.exe -add "out.hevc:fps=24:colr=nclx,bt709,bt709,bt709,off" -new out.mov
  ("off" = full_range_flag 0 = limited/TV; "on" = full range.)
  Audio: remux separately (ffmpeg) then `mp4box -add out.mov -add audio.m4a -new final.mov`
  OR add the audio track in the same MP4Box call — deferred to EX-2/EX-4.
